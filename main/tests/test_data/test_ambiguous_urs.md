# Ambiguous System for Low Confidence Testing

## URS-AMBIGUOUS-001: Hybrid Data Management Platform
**Purpose**: Test consultation trigger

### 1. System Overview
This system combines multiple technologies and approaches:
- Some vendor-supplied components (Category 3?)
- Some custom configuration (Category 4?)
- Some custom development (Category 5?)
- Some infrastructure elements (Category 1?)

### 2. Functional Requirements
- **URS-AMB-001**: The system shall use a combination of off-the-shelf and custom software components.
- **URS-AMB-002**: Data processing algorithms will be partially customized from vendor defaults.
- **URS-AMB-003**: The user interface requires moderate customization.
- **URS-AMB-004**: Integration with existing systems requires custom APIs.
- **URS-AMB-005**: Some business logic will be configured, some will be developed from scratch.

### 3. Technical Requirements  
- **URS-AMB-006**: Database schema follows vendor standard with custom tables added.
- **URS-AMB-007**: Reporting uses vendor tools with custom report templates.
- **URS-AMB-008**: Workflow engine configuration with some custom workflow steps.
- **URS-AMB-009**: Authentication integrates with corporate LDAP and custom roles.

### 4. Regulatory Compliance
- **URS-AMB-010**: System must comply with 21 CFR Part 11 for electronic records.
- **URS-AMB-011**: Audit trail requirements for pharmaceutical validation.
- **URS-AMB-012**: Data integrity requirements per ALCOA+ principles.

### 5. Validation Approach
This system presents challenges in GAMP-5 categorization due to its hybrid nature:
- Contains elements of multiple categories
- Mixed vendor/custom components  
- Unclear primary categorization
- Requires human expertise for proper classification

**Note**: This URS is intentionally ambiguous to test the human consultation system when AI confidence is low.
