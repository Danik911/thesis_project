## Design Decisions

1. **Workflow Root Tracing**
   - **Decision:** Instrument `start_unified_workflow` step method (workflow entry point)
   - **Rationale:** LlamaIndex workflows use `@step` decorators, not traditional `run()` methods. The `start_unified_workflow` step is the first entry point after workflow instantiation.
   - **Implementation:** Added `@observe(name="unified-workflow-execution", as_type="span")` with trace context including user_id, job_id, and GAMP-5 metadata.

2. **OQ Generation Step Tracing**
   - **Decision:** Instrument `complete_workflow` method with generation completion metadata
   - **Rationale:** This method receives the OQTestSuiteEvent and compiles final results - critical point for test suite generation visibility.
   - **Implementation:** Added metadata logging at start (gamp_category, test count, strategy) and output logging at completion (test_count, test_suite_present, workflow_duration).

3. **GAMP-5 Categorization Agent**
   - **Decision:** Instrument `categorize_with_pydantic_structured_output` function (main categorization entry point)
   - **Rationale:** This is the primary categorization function used by the workflow, not the legacy FunctionAgent approach.
   - **Implementation:** Added metadata (urs_length, agent name, document_name) and output (gamp_category, confidence_score, review_required).

4. **OQ Test Case Generation**
   - **Decision:** Instrument `generate_oq_tests` step in OQGenerationWorkflow
   - **Rationale:** This step orchestrates actual test case generation - critical for measuring generation duration and test coverage.
   - **Implementation:** Added metadata (requirement_count, gamp_category, strategy) and output (test_count, coverage_percentage, duration).

5. **ChromaDB RAG Query Tracing**
   - **Decision:** Instrument `query` method in ChromaVectorStoreAdapter
   - **Rationale:** RAG retrieval latency impacts workflow performance - tracing enables performance optimization.
   - **Implementation:** Added metadata (query_length, top_k, collection, filters_applied) and output (result_count, avg_relevance_score).

6. **Phoenix Removal Decision**
   - **Decision:** Removed Phoenix initialization from worker_executor.py (lines 60-66)
   - **Rationale:** Task 2.3 mandates complete migration to Langfuse. Phoenix coexistence violates this requirement and creates observability confusion.
   - **Implementation:** Removed setup_phoenix() import and initialization block. Unified workflow still has Phoenix setup (handled separately).

7. **Zero Fallback Logic Enforcement**
   - **Decision:** NO try-except blocks around `@observe` decorators, NO conditional instrumentation
   - **Rationale:** Langfuse initialization errors must fail explicitly for regulatory compliance. Silent fallbacks mask system failures.
   - **Implementation:** All decorators unconditional, errors propagate to system logs.
