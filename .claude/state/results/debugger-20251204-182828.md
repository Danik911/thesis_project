### Issue Description
The user reported a contradiction:

### Root Cause Identified

The code at `context_provider.py` lines 489-492 has a **silent exception handler**:

```python
for key, name in collection_configs.items():
    try:
        self.collections[key] = self.chroma_client.get_collection(name=name)
        self.logger.info(f"Found existing collection '{name}': {self.collections[key].count()} documents")
    except Exception:  # <-- SWALLOWS ALL EXCEPTIONS WITHOUT LOGGING
        self.collections[key] = self.chroma_client.get_or_create_collection(name=name)
        self.logger.info(f"Created new collection '{name}'")
```

When `get_collection("regulatory_documents")` fails (for whatever reason), the exception is silently caught and a NEW EMPTY collection is created instead. This explains why:
- init_chromadb.py sees 230 documents (opens database directly with list_collections)
- Context Provider sees 0 documents (get_collection() fails, creates new empty collection)

### Why get_collection() Might Fail

Potential reasons (cannot determine without the actual exception):
1. **Collection name mismatch** - The collection might be stored with different casing or metadata
2. **SQLite lock** - Another process might still have a lock from init_chromadb.py's `del debug_client`
3. **ChromaDB version schema issue** - Different ChromaDB behaviors between versions
4. **Path resolution difference** - Context Provider might resolve to a different path
5. **Collection metadata mismatch** - ChromaDB 1.0+ might require exact metadata match

### Why It Occurred
The original code was written with `except Exception:` as a catch-all to handle "collection not found" cases. However, this pattern:
1. Masks ALL exceptions, not just "collection not found"
2. Provides no diagnostic information when failures occur
3. Makes debugging AWS-specific issues nearly impossible
