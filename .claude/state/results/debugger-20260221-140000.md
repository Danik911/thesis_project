## Issues Addressed

1. XLSX export fails with `ValidationError` when a component references a truncated analysis name (e.g., `SITE_IDENTITY`) that does not exactly match any canonical analysis name (`SITE_IDENTITY_CTL`, `SITE_IDENTITY_META`).

---

## Root Cause Analysis

**Issue:** `_normalize_analysis_refs` in `data_normalizer.py` only performs exact key lookup against the `analysis_name_map`. When LlamaExtract returns a truncated or abbreviated analysis name (like `SITE_IDENTITY` instead of `SITE_IDENTITY_CTL`), the exact lookup fails, the component retains the truncated value, and the MDATemplate cross-sheet integrity validator rejects it.

**Why it occurred:** The original implementation assumed analysis references from LlamaExtract would always exactly match the canonical analysis names (or their aliases). In practice, LlamaExtract sometimes returns abbreviated names -- particularly for analyses with suffixed variants like `_CTL` and `_META`.

**Fix approach:** Add a `_resolve_analysis_name` function that tries matching in order: (1) exact match, (2) prefix match (single result), (3) prefix match (multiple results, pick shortest), (4) substring containment (single result). Also update the XLSX export endpoint to call `_normalize_analysis_refs` on stored data before validation, since existing data may contain unresolved truncated references.
