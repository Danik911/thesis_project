## Design Decisions

1. **approve_job() is the ONLY path to APPROVED** - The `update_status()` function explicitly blocks `LIMSJobStatus.APPROVED` with a clear error message directing callers to use `approve_job()`. This architectural decision ensures the HITL gate cannot be bypassed by any code path.

2. **Rollback-on-failure for edits** - Before applying any edit, a deep copy snapshot is taken. If `MDATemplate.model_validate()` fails after the edit, the snapshot is restored. This ensures the MDA template is always in a valid state.

3. **Config injection via LIMSConfig parameter** - The chat agent accepts `config: LIMSConfig` as a parameter to `chat()` instead of using `os.getenv()` directly, consistent with L4a patterns.

4. **In-memory stores for PoC** - Both `_jobs` and `_sessions` are module-level dicts. Acceptable for PoC scope; production would use a database.

5. **TTL and turn limits as hard errors** - `TimeoutError` for TTL expiry and `ValueError` for turn limit. No silent degradation.

6. **Chat only in PENDING_REVIEW** - The `/chat` endpoint returns HTTP 409 if the job is not in PENDING_REVIEW state, preventing edits after approval.

7. **Export returns HTTP 403 for non-APPROVED** - The `/export` endpoint strictly requires APPROVED status, not just any later state.
