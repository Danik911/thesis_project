## Root Cause Analysis

### Issue Description
The Context Provider agent was failing with the error:
```
CRITICAL: Context Provider cannot execute - ALL ChromaDB collections are empty.
Empty collections: ['gamp5', 'regulatory', 'best_practices']
```

### Root Cause
**Complete collection name mismatch** between the code and the actual ChromaDB database:

| What context_provider.py expected | What actually exists in ChromaDB |
|-----------------------------------|----------------------------------|
| `gamp5_documents` | (none) |
| `regulatory_documents` | (none) |
| `sop_documents` | (none) |
| `best_practices` | (none) |

**Actual collection in ChromaDB:** `pharmaceutical_regulations` (15 documents)

The `_initialize_chromadb` method was calling `get_or_create_collection()` with collection names like `gamp5_documents`, `regulatory_documents`, etc. Since these collections do NOT exist in the ChromaDB database (which only has `pharmaceutical_regulations`), ChromaDB was CREATING new empty collections instead of finding existing populated ones.

### Why It Occurred
1. The ChromaDB at `main/chroma_db/` was populated using a different script/method that created a SINGLE collection named `pharmaceutical_regulations`
2. The `context_provider.py` code was written expecting FOUR separate collections with different names
3. When the ChromaDB tarball was uploaded to S3 and downloaded to ECS, the collection names remained as `pharmaceutical_regulations`
4. The `get_or_create_collection` API will create a new empty collection if the requested name doesn't exist

### Fix Approach
Modified `context_provider.py` to use the ACTUAL collection name that exists in the database (`pharmaceutical_regulations`), mapping all dictionary keys (`gamp5`, `regulatory`, `sops`, `best_practices`) to the same collection.
