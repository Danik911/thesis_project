## Design Decisions

### 1. axe-core Integration via Dynamic Imports
**Decision:** Use dynamic imports with client-side and development-only checks
**Rationale:**
- Prevents SSR errors (typeof window !== 'undefined')
- Avoids production bundle bloat (process.env.NODE_ENV !== 'production')
- Enables zero-configuration runtime testing during development
- Outputs violations to browser console automatically

**NO FALLBACK LOGIC:** If axe-core fails to initialize, error is thrown explicitly with full diagnostic message. No silent failure or fallback to "accessibility OK" state.

### 2. ARIA Landmarks Strategy
**Decision:** Use explicit ARIA roles (role="banner", "navigation", "main", "contentinfo") even though some are implicit in HTML5
**Rationale:**
- Maximum compatibility with older screen readers
- Pharmaceutical validation requires explicit traceability
- Clear intent for auditors reviewing HTML structure
- WCAG 1.3.1 best practice for pharmaceutical applications

### 3. Focus Management on Route Changes
**Decision:** Programmatically move focus to main content area on Next.js client-side navigation
**Rationale:**
- Next.js Pages Router does not handle focus management automatically
- WCAG 2.4.3 requires logical focus order
- Screen reader users need to know content changed
- Pharmaceutical validation testing efficiency requires clear focus state

**Implementation:** useEffect hook listening to router.events.on('routeChangeComplete')

### 4. Table Accessibility Approach
**Decision:** Use sr-only caption with visible heading above table
**Rationale:**
- Caption required by WCAG 1.3.1 for screen readers
- Visual design prefers heading outside table
- sr-only class hides caption visually while preserving semantic structure
- Pharmaceutical data tables require clear context for audit review

### 5. ARIA Live Region Politeness Levels
**Decision:**
- aria-live="polite" for loading states
- aria-live="assertive" for error states
**Rationale:**
- Loading states non-critical (user can wait)
- Error states critical (pharmaceutical applications require immediate awareness)
- Follows WCAG 4.1.3 best practices
- Aligns with pharmaceutical safety requirements (drug interactions, validation failures)

### 6. NO FALLBACK LOGIC Enforcement
**Decision:** All error states throw explicitly or display with full diagnostics
**Rationale:**
- Regulatory compliance requires honest system state reporting
- Silent failures in pharmaceutical systems can cause patient safety issues
- GAMP-5 validation requires complete audit trail
- ALCOA+ principles demand accurate and complete data
