## Issues Addressed

### Issue: 401 Authentication Retry Storms
When user navigates to "history" tab during job processing, multiple 401 errors flood the console because:
- Two independent polling mechanisms run concurrently:
  1. `pollJobStatus()` in `main/frontend/pages/generate.tsx` (2-second interval)
  2. `useJobStatusPolling` hook in `main/frontend/hooks/useJobStatusPolling.ts` (5-second interval)
- Each has its own 5-retry exponential backoff (2s, 4s, 8s, 16s, 32s)
- Clerk JWT expires after 60 seconds
- Both polling mechanisms retry independently, creating up to 10 parallel retry attempts

## Root Cause Analysis

**Root Cause:** Uncoordinated token refresh across multiple polling mechanisms

When the JWT token expires:
1. `pollJobStatus` (2s interval) receives 401, starts retry with forced refresh
2. `useJobStatusPolling` (5s interval) receives 401, starts its own retry with forced refresh
3. Each mechanism has 5 retries with exponential backoff
4. Result: 10 parallel token refresh attempts flooding the console

**Contributing Factors:**
- No singleton coordination for token refresh
- No AbortController to cancel stale requests on navigation
- Each polling loop maintained its own retry state independently
