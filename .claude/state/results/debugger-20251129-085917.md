## Root Cause Analysis

### Issue: HIL Approval Workflow Immediately Fails

**Description:**
After adding progress tracking fields to the worker code, the HIL workflow would:
1. Set job to AWAITING_APPROVAL correctly
2. Immediately fail on the first database update in `_update_job_stage()`
3. Job marked as FAILED before user could submit approval

**Root Cause:**
Database schema mismatch. The `postgres-init.sql` script was updated to include three new progress tracking columns:
- `current_stage VARCHAR(50)`
- `stage_started_at TIMESTAMPTZ`
- `stages_completed TEXT[]`

However, the PostgreSQL database was initialized BEFORE these columns were added. The init script only runs once on first container startup (when volume is empty), so existing databases did not have these columns.

When `_update_job_stage()` called `db_job_repo.update(job)`, the SQL query referenced non-existent columns:
```sql
UPDATE jobs SET
    ...
    current_stage = $13,      -- DOES NOT EXIST
    stage_started_at = $14,   -- DOES NOT EXIST
    stages_completed = $15,   -- DOES NOT EXIST
    ...
WHERE job_id = $1
```

This caused `asyncpg.exceptions.UndefinedColumnError`, which was caught and logged silently in `_persist_job_state()`. However, this caused the job state to not be properly persisted to the database, leading to inconsistent state between in-memory and database.

**Why It Occurred:**
1. Progress tracking feature was added to `worker.py` and `job_repository.py`
2. `postgres-init.sql` was updated with new columns
3. But existing running database was not migrated
4. Init scripts only run on fresh databases (empty volume)

**Fix Approach:**
Add the missing columns to the existing database using ALTER TABLE statements.
