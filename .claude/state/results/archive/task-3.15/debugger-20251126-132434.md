## Issues Addressed

### Issue: Langfuse `trace` AttributeError
**Error Message:**
```
AttributeError: 'Langfuse' object has no attribute 'trace'
  File "/app/main/api/app.py", line 361, in submit_job
    trace = langfuse.trace(
            ^^^^^^^^^^^^^^
```

**Context:** Task-executor replaced `@observe` decorator with manual `langfuse.trace()` calls to fix file upload serialization issues. However, the Langfuse SDK 3.5.2 does NOT have a `trace` method on the `Langfuse` class.

## Root Cause Analysis

### Investigation
1. Checked Langfuse SDK version in `pyproject.toml`: `langfuse==3.5.2`
2. Queried Context7 for Langfuse Python SDK documentation
3. Verified SDK API with direct Python test:
   ```python
   from langfuse import Langfuse
   lf = Langfuse(public_key='test', secret_key='test', host='http://localhost:3000')
   print(f'start_span exists: {hasattr(lf, "start_span")}')  # True
   print(f'trace exists: {hasattr(lf, "trace")}')            # False
   ```

### Root Cause
**The Langfuse Python SDK 3.5.2 uses `start_span()` for manual tracing, NOT `trace()`.**

The Context7 documentation confirms:
- `langfuse.start_span(name="...", input={}, metadata={})` - Creates a span manually
- `span.update(output={}, level="...")` - Updates span with results
- `span.end()` - Closes the span
- `langfuse.flush()` - Sends pending spans to server

The `trace()` method does NOT exist in SDK 3.5.2. The `observability.py` file had fallback logic checking `hasattr(self.client, 'trace')` which indicated uncertainty about the API, but the actual usage in `app.py` didn't have this protection.
