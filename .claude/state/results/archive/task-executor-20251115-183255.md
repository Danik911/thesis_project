## Design Decisions

### 1. Two-Tier Storage Architecture
**Decision:** Use LocalStack S3 for document storage + PostgreSQL pgvector for vector storage (NOT "S3VectorStore")

**Rationale:**
- Task description mentioned "S3VectorStore" which is misleading
- Actual architecture (Task 1.2): S3 for raw documents, pgvector for embeddings
- This mirrors production: AWS S3 → Aurora pgvector
- Allows testing complete pipeline: upload → vectorize → retrieve

### 2. MockLLM vs Custom Fake Provider
**Decision:** Use built-in `MockLLM` from `llama_index.core.llms`

**Rationale:**
- MockLLM available in llama-index-core (already installed)
- Deterministic responses (no randomness)
- No external API calls (security)
- Simpler implementation than custom provider
- Tracks token usage for cost analysis

### 3. Cleanup Strategy: Explicit Error Propagation
**Decision:** All cleanup errors must raise exceptions (NO silent failures)

**Rationale:**
- NO FALLBACK LOGIC compliance requirement
- Test pollution detection (cleanup failures indicate issues)
- Full diagnostic information for debugging
- Prevents resource leaks in LocalStack/PostgreSQL

### 4. ALCOA+ Audit Trail Implementation
**Decision:** Dedicated `TestAuditContext` class with fixture-based lifecycle

**Rationale:**
- Captures all 9 ALCOA+ principles automatically
- JSON export for compliance evidence
- Unique test_id per execution (traceability)
- Post-test export ensures data preserved even on failures

### 5. Phoenix Tracing: Environment-Gated
**Decision:** Only enable Phoenix tracing if `ENVIRONMENT=local`

**Rationale:**
- Prevents production leakage (critical security requirement)
- Trace exports added to .gitignore
- Manual export for compliance evidence when needed
- No performance overhead in CI/production tests

### 6. Fixture Scope Strategy
**Decision:** `wait_for_localstack` = session scope, all others = function scope

**Rationale:**
- LocalStack readiness check once per session (efficiency)
- S3 bucket per test (isolation, no pollution)
- pgvector store per test (TRUNCATE cleanup, preserves schema)
- Sample documents per test (mutable metadata protection)

### 7. Mock Embedding Model
**Decision:** Use `MockEmbedding(embed_dim=1536)` instead of real embedding API

**Rationale:**
- No real API calls to OpenAI (cost savings, speed)
- Deterministic embeddings (reproducible tests)
- Matches production dimension (1536 for text-embedding-3-small)
- Security: No credential leakage in tests
