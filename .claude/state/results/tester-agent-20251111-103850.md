### Issue 3: Double File Read (MEDIUM)

**Severity:** MEDIUM (Performance inefficiency)

**Location:** `main/api/dependencies.py:195-216` and `main/api/app.py:160`

**Problem:**
1. **Validator reads file** (dependencies.py:196):
   ```python
   content = await file.read()  # First read
   ```
2. **Validator creates BytesIO** (dependencies.py:216):
   ```python
   file.file = io.BytesIO(content)  # Store in memory
   ```
3. **Endpoint reads AGAIN** (app.py:160):
   ```python
   urs_content = await file.read()  # Second read (from BytesIO)
   ```

**Analysis:**
- BytesIO approach avoids reading from network/disk twice (good)
- BUT endpoint doesn't know validator already read content
- Endpoint calls `await file.read()` which reads from BytesIO (redundant)
- Content already available but not passed to endpoint

**Better Approach:**
```python
# dependencies.py
async def validate_upload_file(file: UploadFile) -> tuple[UploadFile, bytes]:
    """Validate and return file with content."""
    content = await file.read()
    # ... validation ...
    file.file = io.BytesIO(content)
    return file, content  # ✅ Return both file and content

# app.py
async def submit_job(
    validated: tuple[UploadFile, bytes] = Depends(validate_upload_file),
    # ... other deps ...

    file, urs_content = validated  # ✅ Reuse validated bytes
    # No need for: urs_content = await file.read()
```

**Impact:**
- Minor performance overhead (BytesIO read is fast)
- Not critical for pharmaceutical compliance
- Code clarity reduced (content read but not obviously reused)
