## Design Decisions

1. **In-Memory Job Storage (Not Aurora)**
   - **Rationale:** Task 3 (Data API scaffolding) is not started yet - Aurora dependency unavailable
   - **Implementation:** Python dict with asyncio.Lock for thread-safe access
   - **Future Migration:** Easy swap to Aurora via repository abstraction pattern
   - **Audit Trail:** File-based audit logs (logs/audit/jobs/) for compliance until Aurora available

2. **asyncio.Queue Over SQS**
   - **Rationale:** Local development mode - zero external dependencies
   - **Implementation:** Pure Python asyncio.Queue for job queueing
   - **Future Migration:** Abstract queue interface (similar to storage/vector providers)
   - **Performance:** Adequate for local testing, SQS integration planned for production

3. **Background Worker as Lifespan Task**
   - **Rationale:** FastAPI lifespan context manager provides clean startup/shutdown
   - **Implementation:** Long-running coroutine created at app startup, cancelled at shutdown
   - **Error Resilience:** Worker catches all exceptions to prevent crash, logs failures explicitly

4. **File Validation Strategy**
   - **Rationale:** Prevent malicious uploads and resource exhaustion
   - **Implementation:**
     - Max size: 100MB (configurable)
     - Allowed extensions: .txt, .pdf, .docx, .md
     - Read ONCE into memory to avoid double-read (validation + processing)
     - Recreate UploadFile with BytesIO to preserve content
   - **Future Enhancement:** python-magic for content-based validation (deferred to avoid dependencies)

5. **Retry Logic with Exponential Backoff**
   - **Rationale:** Transient failures common in distributed systems
   - **Implementation:**
     - Attempt 1: Immediate
     - Attempt 2: After 1 second
     - Attempt 3: After 2 seconds
     - Attempt 4: After 4 seconds
     - Max 3 retries (4 total attempts)
   - **Audit Trail:** Every retry logged with error context

6. **Mock User Authentication**
   - **Rationale:** Clerk authentication (Task 1.4) not implemented yet
   - **Implementation:** Mock user ID "mock_user_dev_001" returned by get_current_user()
   - **Future Migration:** Replace with Clerk JWT validation (straightforward swap)

7. **SHA-256 Hash Computed Once**
   - **Rationale:** Avoid reading file twice (validation + hashing)
   - **Implementation:** Compute hash from in-memory content after validation
   - **Compliance:** ALCOA+ Original principle - hash verifies file integrity

8. **Dependency Injection Pattern**
   - **Rationale:** Testability and configurability
   - **Implementation:**
     - Storage adapter from Task 1.1
     - Job queue, repository, lock via factory functions
     - User authentication via mock function (swap for Clerk later)
   - **Testing:** FastAPI dependency overrides enable mocking in tests
