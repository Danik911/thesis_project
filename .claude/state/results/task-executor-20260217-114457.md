## Design Decisions

1. **12-section structured prompt**: Organized into clearly numbered sections with
   visual separators (========) for readability and maintainability. Sections cover:
   three-analysis pattern, naming conventions, result type classification,
   misclassification warnings, CalcVariable rules, Calculation rules,
   cross-sheet integrity, analysis defaults, component ordering, valid enums,
   output format, and a pre-output checklist.

2. **Explicit anti-pattern documentation**: Section 4 (Common Misclassification Warnings)
   dedicates ~40 lines to the six most frequent LLM errors (equipment as L instead of K,
   reagents as L instead of K, timers as N instead of K, etc.) with rationale. This is
   the highest-value section for generation accuracy.

3. **Cross-sheet integrity mirrored from validators**: Section 7 explicitly restates
   every Pydantic validator rule from `mda_schema.py` so the LLM can self-check before
   emitting output. This includes the K-type -> Calculation requirement, the A-type
   CalcVariable -> reference_analysis requirement, and the CTL/META -> QC_SAMPLES rule.

4. **Process checklist at the end**: Section 12 provides a mental checklist the LLM
   should run through before finalizing output, reducing the chance of integrity violations.

5. **No fallback statement in prompt**: The prompt explicitly states "Invalid output will
   be rejected outright -- there is no fallback" to set expectations with the LLM.

6. **Concrete JSON examples in output format**: Section 11 shows representative JSON
   for all four arrays (analyses, components, calc_variables, calculations) so the LLM
   has a structural template to follow.
