## Root Cause Analysis

### Investigation Process

1. **Analyzed Frontend Flow:**
   - `generate.tsx` uses lazy initialization to restore state from localStorage on mount
   - If localStorage has an old job with status='PENDING', the UI immediately shows PENDING
   - The `useEffect` at line 292-322 was supposed to resume polling but had critical flaws

2. **Identified Root Cause:**
   The frontend has a **stale localStorage state problem**:

   - When user visits the page, state is restored from localStorage BEFORE validation
   - If the previous job's server was restarted (losing in-memory jobs), the job no longer exists
   - The frontend showed PENDING status from localStorage without verifying the job still exists on server
   - Polling errors were **silently swallowed** (line 284-287 of old code):
     ```javascript
     } catch (e) {
         console.error("Polling failed:", e);
         // Don't fail immediately on one polling error, but maybe log it
     }
     ```
   - This is a **NO FALLBACK LOGIC violation** - errors should be exposed, not hidden

3. **Why No POST Request Appeared:**
   The user likely never clicked "Generate Test Suite" - they were seeing restored state from a previous session. The localStorage had:
   - `activeJobId` = old UUID from previous session
   - `activeJobStatus` = 'PENDING'

   Since the page loaded with PENDING status, the user saw the JobProgress component, NOT the file upload screen.

### Root Cause Summary
**Stale localStorage state combined with silent error handling** caused the frontend to display an outdated job status without proper server validation or error exposure.
