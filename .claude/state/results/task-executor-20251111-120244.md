## Design Decisions

### 1. Manual JWT Verification with PyJWT (vs Clerk SDK)
**Decision:** Use `pyjwt==2.9.0` for JWT verification instead of `clerk-backend-api` SDK's `authenticate_request()` method.

**Rationale:**
- **Networkless verification:** PyJWT verifies tokens locally using PEM public key (no network call to Clerk API)
- **Lower latency:** Eliminates round-trip time for every request
- **Simpler dependency:** PyJWT is lightweight (vs full SDK)
- **JWKS caching design:** Future implementation can cache keys with 15-minute TTL (Task 2+ if needed)
- **Compatible with FastAPI:** Works seamlessly with HTTPBearer security

**Trade-off:** Manual key rotation handling (vs SDK auto-rotation), acceptable for MVP.

### 2. Clock Skew Tolerance: 10 Seconds
**Decision:** Set JWT expiration validation `leeway=10` seconds.

**Rationale:**
- **Development:** Local system clocks may drift (Windows hosts)
- **Clerk default:** Clerk's JavaScript SDK uses 5 seconds, we chose 10 for flexibility
- **Security vs usability:** 10 seconds prevents false rejections while maintaining security
- **NTP assumption:** Production servers will use NTP synchronization (can reduce to 5 seconds)

### 3. Extended AuditLogEntry Model with ALCOA+ Fields
**Decision:** Add `user_email`, `token_iat`, `ip_address`, `session_id` to `AuditLogEntry`.

**Rationale:**
- **ALCOA+ Attributable:** Email provides human-readable attribution (vs Clerk user ID)
- **ALCOA+ Contemporaneous:** Token `iat` tracks authentication lifecycle
- **ALCOA+ Complete:** IP address and session ID enable forensic analysis
- **GAMP-5 traceability:** Full user context for pharmaceutical compliance
- **Non-breaking:** All new fields are optional (`| None`), backward compatible

### 4. Fail-Closed Authentication (NO FALLBACK LOGIC)
**Decision:** All authentication errors raise `HTTPException(401)` with explicit details.

**Rationale:**
- **Zero tolerance policy:** NO default users, NO placeholder tokens, NO artificial confidence scores
- **Pharmaceutical compliance:** GAMP-5 requires explicit failure tracking
- **Security best practice:** Fail-closed prevents unauthorized access
- **Audit trail:** All 401 errors logged with failure reason
- **Debugging:** Explicit error messages aid troubleshooting (no silent failures)

### 5. Environment Variable Configuration (vs Clerk SDK Default)
**Decision:** Require explicit `CLERK_PEM_PUBLIC_KEY`, `CLERK_ISSUER`, optional `CLERK_JWT_AUDIENCE`.

**Rationale:**
- **EU data residency:** Pharmaceutical data must remain in EU (optional `CLERK_SERVER_URL`)
- **Explicit configuration:** No implicit defaults that could violate compliance
- **Validation on startup:** Missing config raises 500 error immediately (vs runtime failure)
- **Security:** Public key must be provided (no auto-fetch from Clerk API)

### 6. Authorization: User Can Only Access Own Jobs
**Decision:** Update `GET /jobs/{job_id}` to check `job.user_id == user.sub`.

**Rationale:**
- **Least privilege:** Users should not see other users' jobs
- **GAMP-5 data isolation:** Pharmaceutical test data segregation
- **Future extensibility:** Foundation for role-based access control (RBAC)
- **Audit logging:** Log unauthorized access attempts
