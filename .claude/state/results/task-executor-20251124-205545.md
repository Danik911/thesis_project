## Implementation Summary

Successfully implemented frontend Human-in-the-Loop (HIL) approval UI for Task 3.14 using Next.js Pages Router, Clerk v6 authentication, and Headless UI components. The implementation provides a complete approval workflow that:

1. **Polls job status** every 5 seconds to detect AWAITING_APPROVAL status

## Design Decisions

### 1. Separate Polling Hook for Approval Status
**Decision:** Created dedicated `useJobStatusPolling` hook that polls `/jobs/{job_id}/approval-status` endpoint every 5 seconds.

**Rationale:**
- Separates approval polling from general job status polling (2-second interval in existing code)
- Cleaner separation of concerns
- Allows different polling intervals for different purposes
- NO FALLBACK LOGIC: All errors exposed explicitly with full diagnostics

### 2. Dark Theme Consistency
**Decision:** Used slate-800/slate-900 backgrounds matching existing UI instead of light backgrounds from task specification.

**Rationale:**
- Maintains visual consistency with existing generate.tsx and history.tsx pages
- Users expect consistent dark theme throughout application
- Better visual hierarchy with color-coded confidence scores against dark backgrounds

### 3. Confidence Score Color Coding
**Decision:** Implemented three-tier color system:
- Red < 70% (Low confidence)
- Amber 70-85% (Moderate confidence)
- Green > 85% (High confidence)

**Rationale:**
- Clear visual communication of AI certainty
- Aligns with pharmaceutical quality standards (typical acceptance thresholds)
- Color contrast meets WCAG 2.1 AA requirements (4.5:1 for text)

### 4. Timeout Display Strategy
**Decision:** Show timeout warning only when < 5 minutes remaining (< 300 seconds).

**Rationale:**
- Avoids cluttering UI during normal workflow
- Provides clear urgency signal when time-sensitive
- Countdown format (MM:SS) matches user expectations from task specification

### 5. Digital Signature Format
**Decision:** Format: `{user_id}_{YYYYMMDDHHMMSS}` (timestamp without separators).

**Rationale:**
- Compact format for storage and display
- Lexicographically sortable
- Matches 21 CFR Part 11 requirements (user ID + timestamp)
- No URL-unsafe characters

### 6. Form Validation Strategy
**Decision:** Client-side validation with server-side enforcement:
- Justification minimum 10 characters (client-side)
- Category override required if APPROVE (client-side)
- Backend validates all constraints (server-side)

**Rationale:**
- Immediate user feedback improves UX
- Server-side validation prevents bypassing (security)
- NO FALLBACK LOGIC: All validation errors surface explicitly

### 7. Modal UX Pattern
**Decision:** Used Headless UI Dialog with Transition animations and fixed backdrop.

**Rationale:**
- Accessibility built-in (focus management, keyboard navigation)
- Consistent with project's existing component library
- Professional polish with enter/leave animations
- WCAG 2.1 AA compliant by default
