## Common Issues & Mitigations

### Task 1.1 (Storage Adapter)

**Issue:** S3 uploads fail with "AccessDenied"
**Root Cause:** IAM role not attached to ECS task
**Mitigation:** Verify `pharma-test-gen-ecs-task` role has S3 permissions:
```bash
aws iam get-role-policy --role-name pharma-test-gen-ecs-task --policy-name task-runtime-permissions
```

**Issue:** Local filesystem writes fail in async context
**Root Cause:** Not flushing filesystem writes before returning path
**Mitigation:** Use `path.write_text()` with explicit flush or `async with aiofiles.open()`

---

### Task 1.2 (Vector Store Provider)

**Issue:** ChromaDB file handles left open
**Root Cause:** Not closing PersistentClient properly
**Mitigation:** Use context manager or explicit `client.close()` in cleanup

**Issue:** Mismatched embedding dimensions (1536 vs 768)
**Root Cause:** Using different embedding model than ChromaDB ingestion
**Mitigation:** Verify embedding model in configuration matches ingestion (text-embedding-3-small = 1536 dims)

---

### Task 1.3 (Job Submission)

**Issue:** Reading uploaded file twice after hashing
**Root Cause:** `await file.read()` consumes stream
**Mitigation:** Store content in memory once, hash and upload from same buffer

**Issue:** Blocking event loop with synchronous SQS boto3 calls
**Root Cause:** Using sync boto3 client in async endpoint
**Mitigation:** Use `aioboto3` or background thread for AWS operations

---

### Task 1.4 (Clerk Auth)

**Issue:** Token verification fails with "Invalid audience"
**Root Cause:** `CLERK_JWT_AUDIENCE` not set or mismatched
**Mitigation:** Copy JWT audience from Clerk dashboard → JWT Templates

**Issue:** Valid tokens rejected due to clock skew
**Root Cause:** Server time differs from Clerk's time
**Mitigation:** Allow 60-second grace period when validating `exp` claim

**Issue:** Logging token contents in CloudWatch
**Root Cause:** Not sanitizing structured logs
**Mitigation:** Use log processor to redact `authorization` headers before emission
