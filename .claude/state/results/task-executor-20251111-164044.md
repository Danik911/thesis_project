## Design Decisions

### 1. Used <Protect> Component Instead of Middleware
**Rationale:** Static export (`output: 'export'`) generates pre-rendered HTML files that cannot execute server-side middleware. The `<Protect>` component provides client-side route protection compatible with static export.

**Implementation:**
- Layout.tsx wraps content in `<Protect fallback={...}>`
- Shows loading spinner while checking authentication
- Redirects unauthenticated users to Clerk sign-in

### 2. Followed examples/alex Layout Pattern Exactly
**Rationale:** examples/alex/frontend provides proven working implementation with Pages Router + Clerk v6 + static export.

**Pattern Matched:**
- Simple ClerkProvider in _app.tsx (no domain prop)
- <Protect> wrapper in Layout component
- useUser() hook for profile display
- UserButton for account management

### 3. NO domain Prop in ClerkProvider
**Rationale:** EU data residency is controlled by the **publishable key** (NOT a domain prop). The domain prop is for multi-domain setups only.

**Current Configuration:**
```tsx
<ClerkProvider {...pageProps}>
  <Component {...pageProps} />
</ClerkProvider>
```

### 4. Loading States on All Auth Checks
**Rationale:** Prevents content flash and hydration errors. Always check `isLoaded` before rendering authenticated content.

**Implementation:**
- index.tsx: Shows loading spinner while auth check
- dashboard.tsx: Shows skeleton loader while user data loads
- Layout.tsx: Shows loading in fallback
