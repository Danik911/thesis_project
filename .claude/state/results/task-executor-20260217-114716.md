## Design Decisions
1. **Separate ChromaDB path**: Uses `./chroma_db_lims/` (not `./chroma_db/`) to keep AI4LIMS data separate from thesis data, matching the pattern in `main/src/lims/config.py`.
2. **Module-level constants**: `CHROMA_PATH` and `COLLECTION_NAME` defined as module constants for reuse across all three functions and easy import by other modules.
3. **openpyxl read_only + data_only**: Uses `read_only=True` and `data_only=True` for memory-efficient parsing of potentially large XLSX files (reads cached values, not formulas).
4. **Text format for embeddings**: Each XLSX is converted to a structured text format (`File: ... Sheet: ... Headers: ... Row N: ...`) that preserves sheet structure while being suitable for ChromaDB's default embedding model.
5. **Site prefix metadata**: Extracts AND/FRE/TUA prefix from filenames and stores as metadata in ChromaDB for potential filtering in future queries.
6. **Bulk add**: All documents are added in a single `collection.add()` call rather than one-at-a-time for performance.
7. **Effective top_k clamping**: `query_similar_templates` clamps `top_k` to `doc_count` to avoid ChromaDB errors when requesting more results than available documents.
8. **No fallback logic**: All error paths raise explicit exceptions with diagnostic messages (FileNotFoundError, ValueError, RuntimeError).

## Known Limitations
1. ChromaDB uses its default embedding model (not OpenAI embeddings) for the `mda_templates` collection. This is intentional to avoid requiring an API key for local development.
2. The `seed_mda_templates` function uses `collection.add()` which will fail if IDs already exist. For re-seeding, the collection should be deleted first or the function should be updated to use `upsert()`.
3. Very large XLSX files with many rows may produce long text strings. ChromaDB handles this via its internal chunking for embeddings.
