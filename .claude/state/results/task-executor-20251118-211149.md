## Design Decisions

### 1. Collection Name Alignment Strategy
**Decision**: Update ingestion scripts to match context provider's collection naming convention
**Rationale**:
- Context provider has an established architecture with 3 distinct collections for filtered retrieval
- Changing consumer expectations would require refactoring collection selection logic
- Ingestion scripts should align to consumer requirements (standard data pipeline pattern)
- Maintains backward compatibility for future collection expansion

### 2. Readiness Guard Placement
**Decision**: Check collection counts AFTER determining which collections to search but BEFORE query embedding
**Rationale**:
- Minimizes wasted API calls (no embedding generation if collections empty)
- Provides comprehensive error message with exact collection names that failed
- Allows granular reporting (e.g., "regulatory_documents: 0, gamp5_documents: 150")
- Fails fast while preserving maximum diagnostic context

### 3. Metadata Filter Graceful Degradation
**Decision**: Treat missing metadata keys as filter mismatch (exclude document)
**Rationale**:
- Maintains strict filtering semantics (NO FALLBACK LOGIC)
- Prevents silent inclusion of documents without required metadata
- Uses `.get()` to avoid KeyError exceptions
- Clear distinction: `None` value = metadata key missing = exclude

### 4. Configuration Validation Timing
**Decision**: Validate required environment variables at `__init__()` time, not during first API call
**Rationale**:
- Fail-fast principle: detect configuration issues immediately at instantiation
- Prevents wasted initialization work (ChromaDB setup, collection creation)
- Provides actionable error message before user submits workflow
- Aligns with GAMP-5 validation requirements (verify prerequisites upfront)

### 5. Seeding Script Idempotency
**Decision**: Check collection counts before ingestion, skip if already populated (unless `--force` flag)
**Rationale**:
- Safe to re-run after failures or Docker restarts
- Prevents duplicate API costs for embedding regeneration
- Supports incremental development workflow
- Maintains ALCOA+ audit trail (timestamps show last ingestion)
