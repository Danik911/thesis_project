## Design Decisions

### 1. Protocol-Based Abstraction Over ABC
**Rationale:** Python typing.Protocol provides compile-time type checking without runtime overhead and allows for structural subtyping. This aligns with modern Python best practices and provides better IDE support compared to ABC (Abstract Base Class).

**Implementation:**
```python
class StorageProvider(Protocol):
    async def save_artifact(...) -> str: ...
    async def retrieve_artifact(...) -> bytes: ...
    async def generate_download_url(...) -> str: ...
```

### 2. Async/Await Throughout
**Rationale:** LlamaIndex workflows require full async support. Using `aiofiles` for local storage and `aiobotocore` for S3 ensures non-blocking operations compatible with the event-driven multi-agent system.

**Trade-off:** Increased complexity vs. consistent async patterns across the entire system.

### 3. Semaphore-Based Concurrency Control
**Rationale:** Prevents resource exhaustion and AWS rate limiting by limiting concurrent operations:
- Local: 10 concurrent file operations (disk I/O bound)
- S3: 5 concurrent operations (network bound, AWS API limits)

**Implementation:**
```python
self._semaphore = asyncio.Semaphore(5)
async with self._semaphore:
    # Protected operation
```

### 4. Metadata Stored Separately for Local, Inline for S3
**Rationale:**
- **Local:** `.meta.json` files allow easy inspection and debugging during development
- **S3:** Object metadata (HTTP headers) provides atomic metadata persistence without additional S3 objects

**ALCOA+ Compliance:** Both approaches maintain audit trail requirements.

### 5. Explicit Error Handling (NO FALLBACK LOGIC)
**Rationale:** Pharmaceutical compliance requires transparent failure modes. All errors propagate with full diagnostic information:
- Missing artifacts → FileNotFoundError with context
- Invalid metadata → ValueError with field details
- S3 API failures → RuntimeError with AWS error codes

**Example:**
```python
raise RuntimeError(
    f"CRITICAL: S3 put_object failed\n"
    f"Artifact ID: {artifact_id}\n"
    f"Bucket: {self.bucket}\n"
    f"AWS Error Code: {error_code}\n"
    f"AWS Error Message: {error_message}"
) from e
```

### 6. Deterministic S3 Key Structure
**Rationale:** Compliance auditing requires predictable artifact locations.

**Structure:**
- `test-suites/{job_id}.json`
- `urs-documents/{job_id}.json`
- `reports/{job_id}.json`

### 7. SSE-KMS Encryption Enforcement
**Rationale:** Data at rest encryption required for pharmaceutical data integrity (ALCOA+ "Original" principle - prevents tampering).

**Implementation:** All `put_object` calls include:
```python
"ServerSideEncryption": "aws:kms",
"SSEKMSKeyId": self.kms_key_id  # Optional customer-managed key
```

### 2. S3 Retrieval Requires Artifact Type Inference
**Limitation:** `retrieve_artifact(artifact_id)` must try multiple S3 key patterns because artifact_type not provided.

**Current Approach:** Try in order:
1. `test-suites/{artifact_id}.json` (most common)
2. `urs-documents/{artifact_id}.json`
3. `reports/{artifact_id}.json`

**Impact:** 1-3 S3 HEAD requests per retrieval on miss.

**Alternative Considered:** Require `artifact_type` parameter in Protocol.
**Decision:** Rejected to maintain simple interface. Performance impact minimal (S3 HEAD requests are fast).

### 3. Local Storage Not Suitable for Production
**Limitation:** Local filesystem lacks:
- Distributed access (multi-instance deployments)
- Durability guarantees (single disk failure)
- Access controls (S3 bucket policies)

**Impact:** None (local mode is dev/test only).

**Mitigation:** Configuration validation warns if production environment uses local storage (future enhancement).

### 4. No Artifact Versioning (Yet)
**Limitation:** Overwriting artifacts with same ID loses previous version.

**Impact:** Reduced auditability for iterative test generation.

**Future Enhancement:** S3 versioning can be enabled in bucket configuration (Task 5.3: Object Lock & Lifecycle).

### 5. S3 Metadata Size Limit (2KB)
**Limitation:** AWS S3 object metadata limited to 2KB total size.

**Impact:** Extended metadata (e.g., large test descriptions) cannot be stored in S3 object metadata.

**Mitigation:**
- Validation enforced at save time (ValueError raised)
- Extended metadata can be stored in artifact body (JSON)
- Core GAMP-5 fields fit comfortably (<500 bytes)
