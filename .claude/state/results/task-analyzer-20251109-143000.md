    effect = "Allow"

## Common Issues & Mitigations

### Issue 1: "AccessDenied: User cannot create OIDC provider"
**Root Cause:** Missing iam:CreateOpenIDConnectProvider permission
**Check:** Verify phase0-complete-policy.json is attached to aiengineer user
```bash
aws iam list-attached-user-policies --user-name aiengineer
```
**Mitigation:** Attach phase0-complete-policy if missing

### Issue 2: "Role already exists"
**Root Cause:** Role was created in a previous run
**Mitigation:** Import into Terraform state:
```bash
terraform import aws_iam_role.deploy pharma-test-gen-deploy
terraform import aws_iam_role.ecs_execution pharma-ecs-execution
terraform import aws_iam_role.ecs_task pharma-ecs-task
```

### Issue 3: IAM Access Analyzer shows "Public access" finding
**Root Cause:** Overly permissive policy (e.g., Resource = "*" without conditions)
**Mitigation:** Add condition keys to scope down permissions:
```hcl
Condition = {
  StringEquals = {
    "s3:x-amz-server-side-encryption" = "aws:kms"
  }
}
```

### Issue 4: GitHub Actions cannot assume deploy role
**Root Cause:** OIDC trust policy mismatch (repo name, branch, etc.)
**Check:** Verify token claims in GitHub Actions logs
**Mitigation:** Update condition in oidc-provider.tf to match actual repo
