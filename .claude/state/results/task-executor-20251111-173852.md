## Design Decisions

### 1. CallbackHandler vs Instrumentation for LlamaIndex
**Decision:** Use `LlamaIndexCallbackHandler` (NOT `Instrumentation`) for LlamaIndex workflow tracing

**Rationale:**
- LlamaIndex Instrumentation has known issues with Workflows (may drop spans due to concurrency)
- CallbackHandler is production-ready and stable with LlamaIndex 0.12.0+
- Provides explicit control over what gets traced vs automatic instrumentation

**Impact:**
- More reliable trace capture for pharmaceutical workflows
- Requires explicit callback manager registration in workflow initialization
- Better debuggability when traces are missing

**Implementation:**
```python
# main/src/core/langfuse_callback.py
langfuse_handler = LlamaIndexCallbackHandler(
    public_key=langfuse_client.public_key,
    secret_key=langfuse_client.secret_key,
    host=langfuse_client.host,
)
callback_manager = CallbackManager([langfuse_handler])
```

### 2. HTTP Basic Auth (NOT Bearer Token) for LangFuse API
**Decision:** Use HTTP Basic Authentication for LangFuse Public API calls

**Rationale:**
- LangFuse Public API uses Basic Auth, NOT Bearer tokens (common implementation mistake)
- Basic Auth format: `Authorization: Basic base64(public_key:secret_key)`
- Bearer token approach will fail with 401 Unauthorized

**Impact:**
- Correct authentication to LangFuse API from Next.js API route
- Prevented common authentication failure scenario
- Explicit documentation in code comments to prevent future mistakes

**Implementation:**
```typescript
// CORRECT - HTTP Basic Auth
const authString = Buffer.from(`${publicKey}:${secretKey}`).toString('base64');
const authHeader = `Basic ${authString}`;

// WRONG - Bearer token (THIS WILL NOT WORK)
// const authHeader = `Bearer ${secretKey}`;
```

### 4. 5-Minute Server-Side Cache for Metrics
**Decision:** Implement 5-minute TTL cache for LangFuse metrics in Next.js API route

**Rationale:**
- LangFuse Cloud has rate limits (~100 requests/minute per API key)
- Polling every 5 seconds would exhaust rate limits quickly
- Metrics don't need real-time updates (5-minute staleness acceptable)
- Balances user experience (fresh data) vs API cost/limits

**Impact:**
- Metrics may be up to 5 minutes stale
- Significantly reduces LangFuse API calls (12 calls/hour vs 720 calls/hour)
- SWR on frontend adds additional client-side caching layer

**Implementation:**
```typescript
// Server-side cache (in-memory, 5-minute TTL)
let metricsCache: { data: LangFuseMetric[]; timestamp: number } | null = null;
const CACHE_TTL_MS = 5 * 60 * 1000; // 5 minutes

// Check cache before fetching
if (metricsCache && (now - metricsCache.timestamp) < CACHE_TTL_MS) {
  return cached data
}
```

### 5. LangFuse Initialization Error Handling (Non-Blocking)
**Decision:** Don't fail FastAPI startup if LangFuse initialization fails

**Rationale:**
- Observability is important but NOT critical for core functionality
- Test generation should work even if tracing fails
- Allows system to run in development without LangFuse credentials
- Errors are logged explicitly (not masked)

**Impact:**
- System remains operational if LangFuse credentials missing or service down
- Clear error messages in logs when LangFuse fails
- Backend can run without observability (degraded mode, not failure)

**Implementation:**
```python
try:
    initialize_langfuse()
    logger.info("LangFuse observability initialized")
except Exception as e:
    logger.error(f"Failed to initialize LangFuse: {e}. Continuing without observability.")
    # Don't fail startup - observability important but not critical
```

### 6. GAMP-5 Metadata Schema (Standardized)
**Decision:** Define mandatory GAMP-5 metadata schema for all traces

**Rationale:**
- Regulatory compliance requires consistent, complete metadata
- ALCOA+ principles mandate attribution, timestamps, traceability
- Standardized schema prevents missing critical fields

**Mandatory Fields (Every Trace):**
- `user_id`: Clerk user ID (ALCOA+ Attributable - WHO)
- `job_id`: Job UUID (GAMP-5 Traceability)
- `gamp_category`: "5" (GAMP-5 Categorization - Category 5 = Fully Configurable)
- `timestamp`: ISO8601 datetime (ALCOA+ Contemporaneous - WHEN)
- `workflow_version`: "1.0" (ALCOA+ Original - VERSION)

**Optional Fields (Context-Specific):**
- `user_email`: Human-readable attribution
- `environment`: "local" | "staging" | "production"
- `error_type`, `error_message`: Error diagnostics (when applicable)

**Impact:**
- Every trace auditable and compliant with pharmaceutical regulations
- Clear ownership and timeline for every operation
- Supports 21 CFR Part 11 audit trail requirements
