# ISSUE-038: LIMS Chat Returns Generic/Unrelated Responses Due to Missing Grounded Context

**Date Created:** 2026-02-21  
**Status:** CLOSED  
**Category:** API / Workflow  
**Priority:** High

## Symptom
- Chat responses in `/lims` are generic or unrelated to the uploaded method.
- The assistant cannot reliably explain where each parameter came from or justify decisions.

## Error/Behavior Details
- `/lims/chat` creates `ChatSession` with only serialized `raw_extraction` text and MDA state.
- Prompt context omits `provenance`, `classification`, `stage_details`, and `conflicts` generated by the two-layer pipeline.
- Prompt truncates context early, reducing retrieval of relevant parameter-level evidence.

## Affected Files
- `main/api/lims_router.py`
- `main/src/lims/chat_agent.py`
- `main/src/lims/prompts/chat_system_prompt.py`

## Root Cause
The `/lims/chat` endpoint instantiated `ChatSession` with only a serialized `raw_extraction` snippet and current MDA JSON. It did **not** pass two-layer pipeline evidence artifacts (`provenance`, `classification`, `conflicts`, `stage_details`, `extraction_trace`), so the LLM lacked the grounding needed for parameter-level attribution and decision explanations.

## Files Modified

| File | Change |
|------|--------|
| `main/api/lims_router.py` | Pass full grounded `chat_context` into chat session creation |
| `main/src/lims/chat_agent.py` | Add workflow context compaction, provenance evidence extraction, grounded prompt building, and `evidence_refs` response field |
| `main/src/lims/prompts/chat_system_prompt.py` | Enforce source-attributed answers using field path + source + confidence + source_detail |

## Code Changes (Before/After)

### Before
- Session context was `pdf_text = json.dumps(job.raw_extraction)` only.
- Prompt only contained MDA JSON + truncated extraction text.
- No explicit contract to cite provenance field paths in explanations.

### After
- Session context includes `pdf_filename`, `raw_extraction`, `classification`, `provenance`, `conflicts`, `stage_details`, `extraction_trace`.
- Chat agent builds compact `workflow_context` and `evidence_refs` from provenance.
- Prompt requires parameter-origin answers to cite path/source/confidence/source_detail, and to state when evidence is missing.
- API response now includes `evidence_refs` for UI/debug traceability.

## Validation
- VS Code diagnostics on changed files: no errors.
- Ruff check confirms no new import/type errors from this fix in edited files.

## Prevention Guidance
1. Treat chat grounding payload as part of `/lims/chat` API contract and keep it in sync with pipeline outputs.
2. Require provenance-aware prompt templates for any reviewer-facing explanation feature.
3. Include a regression test that asserts chat context contains provenance and classification keys before LLM invocation.
