## Issues Encountered & Solutions

### Issue 1: QEMU Emulation Crashes (ARM64 → AMD64)
**Problem:** Building AMD64 Docker images on ARM64 hardware (Snapdragon X Elite) caused QEMU segfaults with UV package manager.
```
qemu: uncaught target signal 11 (Segmentation fault)
```

**Solution:** Created pip-based Dockerfiles that are QEMU-compatible:
- `Dockerfile.api.pip` - Uses pip instead of UV
- `Dockerfile.worker.pip` - Uses pip instead of UV
- `requirements-prod.txt` - Pinned production dependencies

**Files Created:**
```
Dockerfile.api.pip
Dockerfile.worker.pip
requirements-prod.txt
```

### Issue 2: ECR Repository Already Exists
**Problem:** After creating ECR repositories via AWS CLI for manual testing, `terraform apply` failed:
```
RepositoryAlreadyExistsException: The repository with name 'pharma-test-gen-api' already exists
```

**Solution:** Used Terraform 1.5+ import blocks to adopt existing resources:
```hcl
import {
  to = module.ecr.aws_ecr_repository.this["api"]
  id = "pharma-test-gen-api"
}
import {
  to = module.ecr.aws_ecr_repository.this["worker"]
  id = "pharma-test-gen-worker"
}
import {
  to = module.ecr.aws_ecr_repository.this["frontend"]
  id = "pharma-test-gen-frontend"
}
```
**Note:** Import blocks were removed after successful import to prevent future conflicts.

### Issue 4: Frontend Missing Clerk Authentication Keys
**Problem:** Frontend returned error page with:
```
Error: @clerk/nextjs: Missing secretKey
Error: @clerk/clerk-react: Missing publishableKey
```

**Solution:**
1. Created Clerk secret in AWS Secrets Manager:
```bash
aws secretsmanager create-secret \
  --name "pharma-test-gen/clerk" \
  --secret-string '{"NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY":"pk_test_...","CLERK_SECRET_KEY":"sk_test_..."}'
```

2. Updated Terraform to inject secrets into frontend ECS task (`aws/terraform/main.tf`):
```hcl
secrets = [
  {
    name      = "NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY"
    valueFrom = "arn:aws:secretsmanager:${var.aws_region}:${data.aws_caller_identity.current.account_id}:secret:${var.project_name}/clerk:NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY::"
  },
  {
    name      = "CLERK_SECRET_KEY"
    valueFrom = "arn:aws:secretsmanager:${var.aws_region}:${data.aws_caller_identity.current.account_id}:secret:${var.project_name}/clerk:CLERK_SECRET_KEY::"
  }
]
```

3. IAM policy already granted access via pattern `pharma-test-gen/*`

## Lessons Learned
1. ARM64 to AMD64 cross-compilation via QEMU is unreliable for Python builds
2. UV package manager is not QEMU-compatible (use pip-based Dockerfiles instead)
3. When ECR repos exist outside Terraform, use import blocks (not `terraform import` CLI)
4. ECS secrets use format `arn:...:secret-name:json-key::` for JSON key extraction
5. Clerk requires both publishable key (client) and secret key (server) in production
6. CI/CD pipelines with native x86 runners are recommended for reliable AMD64 builds
