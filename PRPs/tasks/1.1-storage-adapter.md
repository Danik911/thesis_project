# Task P1.1 – Implement Dual-Mode Storage Adapter

## What to Do
- Create a storage abstraction that writes URS documents and generated test suites either to local filesystem (dev) or S3 (AWS) based on configuration.
- Ensure metadata (category, timestamps, authorship) is persisted for audit requirements when storing in S3.
- Provide helper methods for retrieving artifacts and generating pre-signed URLs for frontend download.

## Dependencies
- Requires IAM roles (Task P0.4) with scoped S3 permissions.

## Best Practices
- Use dependency injection to decouple storage provider from workflow logic.
- When using S3, enforce server-side encryption (SSE-KMS) and bucket key policies.
- Name S3 keys deterministically (`test-suites/{job_id}.json`) to ease retrieval and compliance auditing.

## Code Example
```python
class StorageAdapter:
    def __init__(self, settings: Settings):
        self.mode = settings.storage_mode  # "local" or "s3"
        if self.mode == "s3":
            self.s3 = boto3.client("s3", region_name=settings.aws_region)
            self.bucket = settings.test_output_bucket

    async def save_test_suite(self, job_id: str, payload: dict) -> str:
        body = json.dumps(payload, indent=2)
        if self.mode == "s3":
            key = f"test-suites/{job_id}.json"
            self.s3.put_object(
                Bucket=self.bucket,
                Key=key,
                Body=body,
                ServerSideEncryption="aws:kms",
                Metadata={"gamp-category": str(payload.get("category"))}
            )
            return f"s3://{self.bucket}/{key}"
        path = Path("output/test_suites") / f"{job_id}.json"
        path.parent.mkdir(parents=True, exist_ok=True)
        path.write_text(body, encoding="utf-8")
        return str(path)
```

## Testing Strategy
- Unit-test storage adapter in both modes using temporary directories and moto/boto3 stubs.
- Verify metadata persistence and encryption in S3 via AWS CLI (`aws s3api head-object`).
- Run integration test in docker-compose scenario to ensure local persistence works with Phoenix tooling.

## Common Issues to Avoid
- Forgetting to flush filesystem writes before returning path (especially in async context).
- Not propagating S3 object versions needed for WORM compliance.
- Hardcoding bucket names rather than reading from configuration.
