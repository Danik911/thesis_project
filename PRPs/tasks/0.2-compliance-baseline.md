# Task P0.2 – Enable Foundational Compliance & Monitoring Services

## What to Do
- Enable AWS CloudTrail organization trail (or account trail) in eu-west-2 with log delivery to the compliance S3 bucket.
- Turn on AWS Config recording for all supported resources; store snapshots in the Object Lock bucket.
- Optionally enable GuardDuty and Security Hub for baseline threat detection.
- Document enabled services and retention policies to satisfy GAMP-5 audit requirements.

## Dependencies
- Requires Task P0.1 (quota validation) to confirm support for required services.

## Best Practices
- Use dedicated KMS keys for CloudTrail and Config log encryption to align with Part 11 controls.
- Enable log file validation in CloudTrail.
- Configure AWS Config conformance packs relevant to security best practices for regulated workloads.

## Code Example
```bash
# Enable CloudTrail
aws cloudtrail create-trail \
  --name pharma-trail \
  --s3-bucket-name pharma-test-output-compliance \
  --is-multi-region-trail \
  --enable-log-file-validation \
  --kms-key-id arn:aws:kms:eu-west-2:123456789012:key/...

aws cloudtrail start-logging --name pharma-trail

# Enable AWS Config recorder
aws configservice put-configuration-recorder \
  --configuration-recorder "name=pharma,roleARN=arn:aws:iam::123456789012:role/AWSConfigRole,recordingGroup={allSupported=true,includeGlobalResourceTypes=true}"
aws configservice start-configuration-recorder --configuration-recorder-name pharma
```

## Testing Strategy
- Verify CloudTrail log delivery to S3 and log file integrity validation.
- Confirm AWS Config recorder status is `ACTIVE` and snapshots exist.
- Run conformance pack compliance report to ensure initial posture visibility.

## Common Issues to Avoid
- Forgetting to enable CloudTrail in all regions (required for security events outside eu-west-2).
- Not assigning proper IAM role to AWS Config, causing recorder failures.
- Missing KMS permissions for CloudTrail/Config to write encrypted logs.
