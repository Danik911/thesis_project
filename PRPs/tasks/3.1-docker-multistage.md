# Task P3.1 – Optimize Docker Multi-Stage Build

## What to Do
- Refactor FastAPI and worker Dockerfiles to use multi-stage builds with slim base images.
- Embed Tini as entrypoint and enable non-root user execution.
- Bake in healthcheck scripts and compile-time dependencies.

## Dependencies
- Requires baseline Dockerfiles from Task 2 and storage adapters from Task P1.1/P1.2.

## Best Practices
- Separate dependency installation and application copy layers to maximize cache hits.
- Keep image size minimal (<200MB) to optimize ECS deployment times.
- Validate license compliance for included packages (ALCOA+ integrity).

## Code Example
```dockerfile
FROM python:3.11-slim AS builder
RUN pip install --upgrade pip poetry
COPY pyproject.toml poetry.lock ./
RUN poetry export -f requirements.txt --output requirements.txt

FROM python:3.11-slim
RUN useradd -m app
COPY --from=builder /requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt
COPY --chown=app:app . /service
USER app
ENTRYPOINT ["/usr/bin/tini", "--"]
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8080"]
```

## Testing Strategy
- Run `docker build` locally and confirm image size reduction.
- Execute container in CI and ensure healthcheck endpoint responds.
- Use Trivy scan to verify no high severity vulnerabilities remain.

## Common Issues to Avoid
- Leaving root user as default, causing compliance findings.
- Forgetting to include runtime deps (libpq, curl) in final stage.
- Skipping healthcheck, leading to ECS perceiving tasks as healthy when not ready.
