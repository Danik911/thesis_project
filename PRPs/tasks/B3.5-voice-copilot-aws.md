# Task B3.5 — Voice Interface for BI Copilot (AWS)

**Phase:** 3.5 (Voice Extension) | **Day:** 3.5 (post-B3 stabilization)
**Dependencies:** B3 (Copilot Chat with Bedrock)
**Branch:** `feature/mes-agentic-bi`
**Status:** NOT STARTED
**Estimated effort:** 1 day

---

## Objective

Add voice interaction to MES Agentic BI copilot by introducing speech-to-text for user input and optional text-to-speech for copilot responses, while preserving the existing B3 Bedrock + tool-use orchestration.

**Target flow:**
Microphone input -> AWS Transcribe Streaming -> transcript text -> existing `/bi/chat/{session_id}` -> copilot text response -> (optional) AWS Polly audio playback.

**Scope rule:** This task extends B3; it must not replace the B3 chat API contract or tool loop.

---

## AWS Service Choice

| Capability | Service | Why |
|-----------|---------|-----|
| Speech-to-text (real-time) | Amazon Transcribe Streaming | Native real-time transcription suitable for conversational UI |
| Text-to-speech (optional) | Amazon Polly | Fast voice playback for copilot responses |
| Conversational bot runtime | Amazon Lex V2 | Not selected for B3.5 (would overlap/restructure custom Bedrock tool loop) |

## Implementation Details

### 1. Voice Input (Transcribe Streaming)

- Start capture from browser mic with explicit user action.
- Stream audio chunks to backend-managed Transcribe Streaming session.
- Return partial + final transcript events to frontend.
- On final transcript, submit text through existing B3 chat call (`POST /bi/chat/{session_id}`).

**Required behavior:**
- No silent fallback logic.
- If mic permission denied or stream initialization fails, show explicit error state and preserve normal text chat input.

### 2. Voice Output (Polly, optional)

- Add a toggle: `Play copilot responses` (off by default).
- If enabled, synthesize response text with Polly and play returned audio.
- Use plain text initially; SSML can be future enhancement.

### 3. Session/State Model

- Voice state is UI-local (`idle | listening | transcribing | error`).
- Copilot state remains in B3 session/chat flow.
- Do not persist raw audio in session store for PoC; persist transcript + chat messages only.

### 4. Security and IAM

- Minimum permissions for API role:
  - `transcribe:StartStreamTranscription`
  - `polly:SynthesizeSpeech` (if TTS enabled)
- Restrict to intended region(s) and service resources where possible.
- Never expose long-lived AWS credentials to browser.

## API Contract (proposed)

| Endpoint | Method | Purpose | Response |
|----------|--------|---------|----------|
| `/bi/voice/session/{session_id}` | POST | Initialize short-lived voice streaming context | `{ voice_session_id, expires_at }` |
| `/bi/voice/transcript/{voice_session_id}` | WS/stream | Emit partial/final transcript events | `transcript events` |
| `/bi/voice/tts/{session_id}` | POST | Synthesize a text response with Polly (optional) | `audio/mpeg` |

Note: transport can be SSE or WebSocket; choose one and keep it consistent across frontend/backend.

## Gate Criteria (Pass/Fail)

- [ ] Voice capture starts/stops from ChatDrawer mic control
- [ ] Spoken input produces final transcript within acceptable latency for PoC
- [ ] Final transcript is submitted through existing B3 `/bi/chat/{session_id}` path
- [ ] Copilot filters/actions triggered by voice behave identically to typed input
- [ ] Optional Polly playback works for assistant responses when enabled
- [ ] Mic permission and stream errors are explicit (no silent fallback)
- [ ] Existing text-only chat path remains unchanged and functional
- [ ] No thesis/LIMS route regressions (`/generate`, `/history`, `/lims`)
