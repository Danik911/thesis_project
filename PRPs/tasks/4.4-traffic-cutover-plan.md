# Task P4.4 – Production Traffic Cutover & Verification

## What to Do
- Draft runbook for staged traffic shift from legacy stack to ECS-based services.
- Execute canary deployment with 10% traffic via ALB target group weight before full promotion.
- Monitor LangFuse, CloudWatch, and SQS metrics during cutover to ensure stability.

## Dependencies
- Requires ECS deployment (Task P4.1), Aurora cutover (Task P4.2), and Bedrock integration (Task P4.3).

## Best Practices
- Coordinate with compliance to schedule cutover window and capture approval signatures.
- Define rollback criteria and automated script to revert ALB target weights.
- Capture evidence (screenshots/log exports) for THESIS_EVIDENCE_PACKAGE submission.

## Links
- [AWS ALB Weighted Target Groups](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/lambda-functions.html#load-balancer-routing-weighing)

## Testing Strategy
- Run synthetic transactions through both old and new stacks before cutover to ensure parity.
- Perform chaos test by terminating one ECS task and confirming auto-recovery.
- Validate LangFuse anomaly alerts trigger appropriately on error spikes.

## Common Issues to Avoid
- Failing to update DNS TTLs ahead of cutover, causing prolonged propagation.
- Neglecting to pause non-essential background jobs during transition.
- Forgetting to notify stakeholders if rollback executed.
