# Task 3.12: Categorization Agent - Universal Ambiguity Detection

## Status
**COMPLETED** ✅ (2025-11-24)

## Priority
**CRITICAL** - Safety and compliance requirement for pharmaceutical test generation

## Objective
Refactor the GAMP-5 categorization agent to detect **ANY** ambiguity across all category boundaries (1/3, 3/4, 4/5) and trigger Human-in-the-Loop (HIL) consultation when uncertain. Enforce conservative "when in doubt, ask human" principle with NO GUESSING.

## Context

**Current Issue** (from Langfuse trace analysis):
- ❌ Agent assigns Category 4 with **100% confidence** to URS labeled "Ambiguous (4/5)" by user
- ❌ Prompt doesn't detect ambiguity signals ("optional custom modules", hybrid characteristics)
- ❌ Confidence threshold too low (0.8) - allows borderline cases to pass without HIL
- ❌ No explicit `requires_human_review` flag in output

**Root Cause**:
Categorization prompt lacks explicit ambiguity detection rules. Agent can claim high confidence even when multiple category interpretations are valid.

**Example Failure** (Job `ee6b41db-bc3d-4a8e-ae4a-84f8b5dca704`):
```
URS: "Personalized Medicine Orchestration Platform"
User Note: "Ambiguous (4/5)"
AI Output: Category 4, confidence=1.0, requires_human_review=false
Expected: Category 4 OR 5, confidence<0.85, requires_human_review=true
```

**New Prompt Structure**:

```python
ENHANCED_CATEGORIZATION_PROMPT = """
# GAMP-5 Software Categorization Task

You are a pharmaceutical regulatory compliance expert tasked with categorizing software systems according to GAMP-5 guidelines.

## GAMP-5 Categories

**Category 1**: Operating systems, firmware, infrastructure (NOT directly affecting product quality)
**Category 3**: Non-configured commercial off-the-shelf (COTS) software
**Category 4**: Configured COTS software (parameterization, NO source code changes)
**Category 5**: Custom-developed software (bespoke code, modifications to COTS source)

## CRITICAL: Universal Ambiguity Detection Rules

Before assigning a category, ANALYZE for ambiguity signals across ALL boundaries:

### Category 1 vs 3 Ambiguity
- Does the URS describe infrastructure (OS, database) OR application software?
- Is it directly affecting product quality? (Yes → Cat 3+, No → Cat 1)
- **IF UNCLEAR** → `requires_human_review = true`

### Category 3 vs 4 Ambiguity
- Is the software used "as-is" (Cat 3) OR does it require configuration/parameterization (Cat 4)?
- Does URS mention: "configured workflows", "customizable settings", "parameter adjustments"?
- **IF BOTH POSSIBLE** → `requires_human_review = true`

### Category 4 vs 5 Ambiguity
- Does the system involve:
  - Configuration only (XML, INI files, GUI settings) → Category 4
  - Custom source code (Python, Java, C#) → Category 5
  - BOTH (hybrid: configured platform + custom modules) → **AMBIGUOUS** → `requires_human_review = true`
- Keywords indicating Cat 4/5 boundary: "optional custom modules", "extensible", "plugin architecture", "API customization"
- **IF UNSURE** → `requires_human_review = true`

### General Ambiguity Signals

**Mandatory HIL triggers** (set `requires_human_review = true` if ANY detected):
- ❌ Keywords: "optional", "customizable", "hybrid", "ambiguous", "unclear", "may include"
- ❌ Conflicting indicators (e.g., "standard package with custom algorithms")
- ❌ Vague/incomplete URS (missing critical details for categorization)
- ❌ Multiple valid interpretations possible
- ❌ Confidence score < 85%

## Conservative Stance Enforcement

**Default Assumption**: When uncertain → `requires_human_review = true`

You must **explicitly justify** why it's NOT ambiguous to set `requires_human_review = false`. Examples:
- ✅ "URS clearly states 'no source code modifications' → definitively Category 4"
- ✅ "System is pure COTS with no configuration mentioned → definitively Category 3"
- ❌ "Probably Category 4 based on typical implementations" → INVALID (use HIL instead)

## Response Format (JSON)

{
    "gamp_category": 4,
    "confidence_score": 0.85,
    "reasoning": "System involves configuration of COTS platform without source code changes. However, URS mentions 'optional custom modules' which suggests potential Category 5 characteristics.",
    "has_ambiguity_signals": true,
    "ambiguity_details": "Category 4/5 boundary detected: 'optional custom modules' indicates potential custom development",
    "requires_human_review": true,
    "alternative_categories": [5]
}

## Mandatory Rules

1. **IF** confidence < 85% → `requires_human_review = true`
2. **IF** any ambiguity keyword detected → `requires_human_review = true`
3. **IF** multiple category interpretations valid → `requires_human_review = true`
4. **IF** URS missing critical details → `requires_human_review = true`
5. **NEVER** set `requires_human_review = false` without explicit justification

## URS Document

{urs_content}

## Task

Analyze the above URS and provide GAMP-5 categorization with ambiguity assessment.
"""
```

**Key Improvements**:
- ✅ Explicit ambiguity rules for ALL category boundaries
- ✅ Mandatory HIL triggers defined
- ✅ Conservative stance enforced
- ✅ Agent must justify certainty, not uncertainty
- ✅ Alternative categories surfaced when ambiguous

from pydantic import BaseModel, Field
from typing import List, Optional

class GAMPCategorizationResult(BaseModel):
    """Enhanced GAMP-5 categorization result with ambiguity detection"""

    category: int = Field(..., ge=1, le=5, description="GAMP-5 category (1, 3, 4, or 5)")
    confidence_score: float = Field(..., ge=0.0, le=1.0, description="Confidence score (0.0-1.0)")
    reasoning: str = Field(..., description="Detailed reasoning for categorization")

    # NEW FIELDS (v2):
    has_ambiguity_signals: bool = Field(
        ...,
        description="True if ANY uncertainty detected (keywords, conflicting indicators, etc.)"
    )
    ambiguity_details: Optional[str] = Field(
        None,
        description="Specific reason for ambiguity (e.g., 'Category 3/4 boundary: configuration unclear')"
    )
    requires_human_review: bool = Field(
        ...,
        description="MANDATORY HIL trigger flag (true if confidence < 0.85 OR ambiguity detected)"
    )
    alternative_categories: Optional[List[int]] = Field(
        None,
        description="Other plausible categories if ambiguous (e.g., [4, 5] for Cat 4/5 boundary)"
    )

    class Config:
        json_schema_extra = {
            "example": {
                "category": 4,
                "confidence_score": 0.75,
                "reasoning": "Configured COTS with optional custom modules",
                "has_ambiguity_signals": True,
                "ambiguity_details": "Category 4/5 boundary: 'optional custom modules' suggests potential Cat 5",
                "requires_human_review": True,
                "alternative_categories": [5]
            }
        }

### Phase 4: Update Categorization Logic (1 hour)

**File**: `main/src/core/categorization_workflow.py`

**Modify `categorize_document` Step**:

```python
@step
async def categorize_document(ctx: Context, ev: InputEvent) -> Union[CategorizationEvent, HumanConsultationRequiredEvent]:
    """
    GAMP-5 categorization with universal ambiguity detection.

    Triggers HIL if:
    - Confidence < 85%
    - Ambiguity signals detected
    - requires_human_review = true
    """
    urs_content = ctx.data.get("urs_content")

    # Call LLM with enhanced prompt
    response = await categorization_agent.arun(
        ENHANCED_CATEGORIZATION_PROMPT.format(urs_content=urs_content)
    )

    # Parse response into GAMPCategorizationResult
    result = GAMPCategorizationResult.parse_raw(response)

    # Store in context
    ctx.data["categorization_result"] = result
    ctx.data["gamp_category"] = result.category
    ctx.data["confidence_score"] = result.confidence_score

    # CRITICAL: HIL trigger logic
    if result.requires_human_review:
        logger.info(
            f"HIL triggered: requires_human_review=true "
            f"(confidence={result.confidence_score}, ambiguity={result.has_ambiguity_signals})"
        )

        # Emit HIL event
        return HumanConsultationRequiredEvent(
            consultation_type="gamp5_categorization",
            reason=result.ambiguity_details or "Low confidence or ambiguity detected",
            current_value=result.category,
            alternative_values=result.alternative_categories or [],
            confidence=result.confidence_score,
            context={
                "reasoning": result.reasoning,
                "has_ambiguity_signals": result.has_ambiguity_signals,
                "ambiguity_details": result.ambiguity_details
            }
        )

    # No HIL needed → proceed with categorization
    logger.info(f"Categorization complete: Category {result.category} (confidence={result.confidence_score})")
    return CategorizationEvent(
        category=result.category,
        confidence=result.confidence_score,
        reasoning=result.reasoning
    )
```

**Key Changes**:
- ✅ Use enhanced prompt with ambiguity rules
- ✅ Check `requires_human_review` flag (not just confidence threshold)
- ✅ Emit `HumanConsultationRequiredEvent` if HIL needed
- ✅ Include ambiguity details in HIL event context
- ✅ Pass alternative categories to human reviewer
