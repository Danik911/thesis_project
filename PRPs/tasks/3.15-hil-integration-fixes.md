## Detailed Issue Analysis

### Issue 1: POST /jobs Hanging - `net::ERR_EMPTY_RESPONSE`

**Status:** ✅ FIXED

**Symptoms:**
- OPTIONS preflight succeeds (200)
- JWT authentication succeeds
- POST /jobs request hangs indefinitely
- Browser shows `net::ERR_EMPTY_RESPONSE` after timeout

**Root Cause:** Langfuse `@observe(name="create_test_generation_job")` decorator on `submit_job()` endpoint
- The `@observe` decorator tries to serialize ALL function inputs for tracing
- File uploads (`UploadFile`) contain non-serializable attributes (file descriptors, SpooledTemporaryFile)
- Serialization blocks indefinitely, connection times out

**Fix Applied:**
- Replaced `@observe` decorator with manual `langfuse.start_span()` context manager
- Only serializes safe metadata: filename, content_type, job_id, user_id
- Added `span.end()` in finally block before `langfuse.flush()`

**File Modified:** `main/api/app.py` (lines ~349-490)

```python
# BEFORE (BROKEN):
@observe(name="create_test_generation_job")
async def submit_job(...):

# AFTER (FIXED):
async def submit_job(...):
    span = None
    if langfuse:
        span = langfuse.start_span(
            name="create_test_generation_job",
            input={
                "filename": file.filename,
                "content_type": file.content_type,
                "endpoint": "POST /jobs"
            },
            metadata={"job_id": job_id, "user_id": user.sub}
        )
    try:
        # ... job submission logic ...
    finally:
        if span:
            span.end()
        if langfuse:
            langfuse.flush()
```

### Issue 2: RecursionError in Logging System

**Status:** ✅ FIXED

**Symptoms:**
```
RecursionError: maximum recursion depth exceeded
  File "/usr/local/lib/python3.12/logging/__init__.py", line 1517, in debug
Exception ignored in: <function WeakValueDictionary.__init__.<locals>.remove at 0xf0eec3de6ac0>
```

**Root Cause:**
- Python's logging manager uses WeakValueDictionary to cache loggers
- During garbage collection, the remove callback tries to log a debug message
- This triggers more logging operations, causing infinite recursion
- Happens when multiple async tasks log concurrently

**Fix Applied:**
1. Moved `logging.basicConfig()` to absolute top of `app.py` (before ANY imports)
2. Set root logger to INFO level (no DEBUG anywhere)
3. Suppressed DEBUG logging for noisy internal modules
4. Added resource warning filter for GC warnings

**File Modified:** `main/api/app.py` (lines 1-40)

```python
# CRITICAL: Configure logging FIRST, before ANY other imports
import logging
import sys
import warnings

# Suppress WeakValueDictionary recursion warnings during GC
warnings.filterwarnings("ignore", category=ResourceWarning)

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s - %(name)s - %(levelname)s - %(message)s",
    stream=sys.stdout,
    force=True
)

# Suppress DEBUG logging for internal modules
logging.getLogger().setLevel(logging.INFO)  # Root logger - no DEBUG anywhere
logging.getLogger("asyncio").setLevel(logging.WARNING)
logging.getLogger("concurrent.futures").setLevel(logging.WARNING)
logging.getLogger("urllib3").setLevel(logging.WARNING)
logging.getLogger("httpx").setLevel(logging.WARNING)
logging.getLogger("httpcore").setLevel(logging.WARNING)
logging.getLogger("opentelemetry").setLevel(logging.WARNING)
logging.getLogger("alembic").setLevel(logging.WARNING)
logging.getLogger("phoenix").setLevel(logging.WARNING)
```

### Issue 9: Token Expiration During Polling (401 Unauthorized)

**Status:** 🔴 BLOCKING - Research complete, needs implementation

**Symptoms:**
```
GET http://localhost:8080/jobs/1e8f1c25-6055-4a03-a175-dcf2c99b6228/approval-status 401 (Unauthorized)
Console: Token expired
```

**Root Cause:**
- Clerk JWT tokens expire after **60 seconds** by default
- Frontend polling hook caches token and reuses it
- Long-running workflows (>60s) cause polling requests to fail
- User sees job stuck even though backend processing continues

**Evidence from Langfuse:**
- First trace: Job submitted at T+0
- HIL triggered at T+45s
- Polling starts at T+45s with valid token
- Token expires at T+60s
- Subsequent polls return 401

**Research Findings (from context-collector):**
1. Clerk's `getToken()` returns cached token until near expiry
2. Must call `getToken()` **before each request** (not once at start)
3. Use `setTimeout` recursion instead of `setInterval` for polling
4. Consider using Clerk's `session.getToken({ template: "..." })` for longer-lived tokens

**Recommended Fix:**

**File to modify:** `main/frontend/pages/generate.tsx` (or wherever polling hook is defined)

```typescript
// BEFORE (broken):
const token = await getToken();  // Called once
setInterval(async () => {
  const res = await fetch(url, { headers: { Authorization: `Bearer ${token}` } });
}, 3000);

// AFTER (fixed):
const pollWithFreshToken = async () => {
  const freshToken = await getToken();  // Fresh token each poll
  const res = await fetch(url, { headers: { Authorization: `Bearer ${freshToken}` } });
  if (shouldContinuePolling) {
    setTimeout(pollWithFreshToken, 3000);  // Recursive setTimeout
  }
};
pollWithFreshToken();
```

### Issue 10: DeepSeek V3 JSON Parsing Failure (OQ Generation)

**Status:** 🔴 BLOCKING - Research complete, needs implementation

**Symptoms:**
```
TestGenerationFailure: Failed to parse DeepSeek V3 JSON response for batch_2
Error at line 77 column 17 (char 4770)
Expecting value: line 77 column 17 (char 4770)
```

**Root Cause:**
- DeepSeek V3 `max_tokens=4000` insufficient for large OQ test batches
- Response truncated mid-JSON, causing parse failure
- batch_2 typically generates 15-20 test cases (~6000-8000 tokens)

**Evidence from Langfuse trace (`after_hil_approval.json`):**
- OQ generation started successfully after HIL approval
- DeepSeek V3 calls with `num_output: 4000`
- batch_1 succeeded (smaller output)
- batch_2 failed at parse stage (truncated JSON)

**Research Findings (from context-collector):**

1. **Token Limit Issue:**
   - 4000 tokens ≈ 3000 words ≈ 16KB text
   - OQ batch with 20 test cases ≈ 6000-8000 tokens
   - Solution: Increase `max_tokens` to 6000-8000

2. **JSON Robustness:**
   - Add `json-repair` library for handling truncated JSON
   - Library can reconstruct partial JSON structures
   - Install: `pip install json-repair`

3. **DeepSeek V3 Best Practices:**
   - Lower temperature (0.3 vs 0.7) for structured output
   - Use explicit JSON schema in prompt
   - Consider streaming for large outputs

**Recommended Fix:**

**File to modify:** `main/src/agents/test_generation_agent.py` (or wherever DeepSeek is called)

```python
# 1. Increase max_tokens
llm_config = {
    "max_tokens": 6000,  # Was 4000
    "temperature": 0.3,  # Lower for structured output
}

# 2. Add json-repair for robustness
from json_repair import repair_json

def parse_response(response_text: str) -> dict:
    try:
        return json.loads(response_text)
    except json.JSONDecodeError:
        # Attempt repair for truncated JSON
        repaired = repair_json(response_text)
        return json.loads(repaired)
```

**Dependencies to add:** `json-repair>=0.25.0`
