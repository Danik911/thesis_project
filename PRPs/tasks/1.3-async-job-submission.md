# Task P1.3 – Refactor FastAPI Job Submission for Async Workflows

## What to Do
- Update FastAPI endpoints to accept URS uploads, persist them via the storage adapter, and enqueue jobs (local in-memory or SQS) without blocking requests.
- Return a job identifier immediately and expose status/result endpoints that query Aurora (or local store) for progress.
- Ensure background execution handles retries and error propagation to the job record.

## Dependencies
- Requires storage adapter (Task P1.1) and initial Data API client scaffolding (Task 3).

## Best Practices
- Use FastAPI dependency injection for the storage adapter and database client to improve testability.
- Keep asynchronous queue submission non-blocking (e.g., use `asyncio.create_task` locally, boto3 async wrapper for SQS later).
- Validate uploaded files (size, type) before processing to prevent malicious inputs.

## Code Example
```python
@router.post("/jobs", response_model=JobResponse)
async def submit_job(
    file: UploadFile = File(...),
    user: ClerkClaims = Depends(require_clerk_user),
    storage: StorageAdapter = Depends(get_storage),
    repo: JobRepository = Depends(get_job_repo),
    queue: JobQueue = Depends(get_job_queue)
):
    urs_bytes = await file.read()
    urs_key = await storage.save_document(file.filename, urs_bytes)
    job_id = await repo.create_pending_job(user_id=user.sub, urs_key=urs_key, urs_hash=hashlib.sha256(urs_bytes).hexdigest())
    await queue.enqueue(job_id=job_id, urs_key=urs_key)
    return JobResponse(job_id=job_id, status="pending")
```

## Testing Strategy
- Unit-test the endpoint using httpx/pytest-asyncio, mocking storage and queue dependencies.
- Integration test in docker-compose environment to ensure local queue execution completes jobs and updates status endpoint.
- Validate that large files (>configured limit) are rejected with appropriate HTTP errors.

## Common Issues to Avoid
- Reading uploaded file twice (after hashing); store content in memory once to avoid duplication.
- Blocking the event loop with synchronous SQS boto3 calls; plan to adopt aioboto3 or background thread for AWS traffic.
- Forgetting to handle `UploadFile.file` closing behavior, leading to resource warnings.
