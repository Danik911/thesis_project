# Task P3.3 – Validate RAG Workflow Locally

## What to Do
- Implement test harness exercising ingestion, vectorization, and retrieval using LocalStack S3-compatible bucket.
- Mock Bedrock DeepSeek responses to ensure deterministic tests.
- Capture local trace data via Phoenix for developer debugging only.

## Dependencies
- Requires Compose stack (Task P3.2) and vector store adapter (Task P1.2).

## Best Practices
- Seed sample document corpus and ensure vector store resets between test runs.
- Use pytest fixtures to isolate ingestion vs retrieval scenarios.
- Keep Phoenix instrumentation limited to local environment variables to avoid production leakage.

## Code Example
```python
@pytest.fixture
def rag_client(localstack_s3_bucket):
    return RagClient(
        vector_store=S3VectorStore(bucket=localstack_s3_bucket),
        llm=FakeBedrockLLM(response="Stubbed"),
    )

def test_retrieval_returns_top_k(rag_client):
    rag_client.ingest("/fixtures/protocol.pdf")
    results = rag_client.query("What is the release workflow?", top_k=3)
    assert len(results) == 3
```

## Testing Strategy
- Run `pytest tests/rag` within Compose container, ensuring LocalStack endpoints are reachable.
- Measure coverage for ingestion modules and retrieval flows.
- Export Phoenix trace sample and attach to compliance evidence folder.

## Common Issues to Avoid
- Forgetting to clean up LocalStack bucket between tests, causing duplication.
- Using real Bedrock credentials in local tests rather than mocks.
- Committing Phoenix dev config or trace exports to repo inadvertently.
