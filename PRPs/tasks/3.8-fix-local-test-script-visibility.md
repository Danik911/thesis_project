## Objective
Make generated test suites automatically visible on the Windows host filesystem without requiring manual `docker cp` extraction from Docker named volumes.

## Context from Task 3.6

**Current Behavior**:
- ✅ Test suites generated successfully inside Docker containers
- ✅ Files stored correctly at `/app/output/{job_id}/test_suite.yaml`
- ❌ Files stored in Docker named volume `output-data`, NOT visible on host
- ❌ Developer must manually run `docker cp` to extract test suites
- ❌ Frontend development blocked (can't test file downloads without manual extraction)

**Discovery**:
After completing all 12 fixes in Task 3.6, workflow successfully generated test suite but user couldn't see files because:
- `docker-compose.dev.yml` uses named volume: `output-data:/app/output`
- Named volumes stored in Docker's internal storage (not host filesystem)
- Files exist in container but invisible in `main/output/` on host

**Langfuse Trace Evidence**:
- Trace ID: `76f363c24dc087450c73d473128d48ad`
- Test suite generated: OQ-SUITE-1947 (10 test cases, ~36KB YAML)
- ALCOA+ audit logs show storage path: `/app/output/test_suites/test_suite_OQ-SUITE-1947_20251118_194757.json`
- Worker saved to: `/app/output/752e623f-b061-4326-ba19-1e4600ff16da/test_suite.yaml`

**Manual Workaround**:
```bash
# Verify files exist in container
docker exec pharma-worker-dev ls -lh /app/output/{job_id}/

# Extract to host
docker cp pharma-worker-dev:/app/output/{job_id} ./main/output/
```

## Implementation Options

### Option A: Change Named Volume to Bind Mount (RECOMMENDED)

**Change**: Modify `docker-compose.dev.yml` to bind mount host directory

**Before**:
```yaml
services:
  api:
    volumes:
      - output-data:/app/output

  worker:
    volumes:
      - output-data:/app/output

volumes:
  output-data:
    driver: local
```

**After**:
```yaml
services:
  api:
    volumes:
      - ./main/output:/app/output:rw  # Bind mount to host directory

  worker:
    volumes:
      - ./main/output:/app/output:rw

# Remove output-data volume definition
# volumes:
#   output-data:
#     driver: local
```

**Benefits**:
- ✅ Immediate visibility on host
- ✅ Simple configuration change
- ✅ Works across all platforms
- ✅ No code changes required
- ✅ Preserves existing volume mount structure

**Drawbacks**:
- ⚠️ Requires data migration from named volume to host directory
- ⚠️ Bind mounts have different performance characteristics (slower on Windows WSL2)

**Migration Steps**:
1. Copy existing data from named volume to host:
   ```bash
   docker-compose -f docker-compose.dev.yml down
   docker cp pharma-worker-dev:/app/output ./main/output/
   ```
2. Update `docker-compose.dev.yml`
3. Restart containers:
   ```bash
   docker-compose -f docker-compose.dev.yml up -d
   ```
4. Verify files visible in `main/output/` on host

### Option C: Keep Named Volume + Add Developer Script (MINIMAL CHANGE)

**Change**: Add convenience script for extracting test suites

**File**: `scripts/extract-test-suites.sh`

```bash
#!/usr/bin/env bash
# Extract all test suites from Docker named volume to host

set -euo pipefail

OUTPUT_DIR="./main/output"
CONTAINER="pharma-worker-dev"

echo "Extracting test suites from Docker container..."

# Get list of job directories
JOB_DIRS=$(docker exec "$CONTAINER" sh -c 'ls -1 /app/output/ 2>/dev/null || true')

if [ -z "$JOB_DIRS" ]; then
    echo "No test suites found in container."
    exit 0
fi

# Extract each job directory
for JOB_ID in $JOB_DIRS; do
    echo "Extracting $JOB_ID..."
    docker cp "$CONTAINER:/app/output/$JOB_ID" "$OUTPUT_DIR/"
done

echo "Extraction complete. Test suites available in $OUTPUT_DIR/"
ls -lh "$OUTPUT_DIR/"
```

**PowerShell Equivalent** (`scripts/extract-test-suites.ps1`):
```powershell
# Extract all test suites from Docker named volume to host

$OutputDir = ".\main\output"
$Container = "pharma-worker-dev"

Write-Host "Extracting test suites from Docker container..."

# Get list of job directories
$JobDirs = docker exec $Container sh -c 'ls -1 /app/output/ 2>/dev/null || true'

if ([string]::IsNullOrWhiteSpace($JobDirs)) {
    Write-Host "No test suites found in container."
    exit 0
}

# Extract each job directory
$JobDirs -split "`n" | ForEach-Object {
    $JobId = $_.Trim()
    if ($JobId) {
        Write-Host "Extracting $JobId..."
        docker cp "${Container}:/app/output/${JobId}" "$OutputDir/"
    }
}

Write-Host "Extraction complete. Test suites available in $OutputDir/"
Get-ChildItem -Path $OutputDir -Directory | Format-Table Name, LastWriteTime
```

**Benefits**:
- ✅ No infrastructure changes
- ✅ Minimal risk
- ✅ Simple bash/PowerShell script

**Drawbacks**:
- ❌ Still requires manual step (running script)
- ❌ Doesn't solve automatic visibility
- ❌ Not integrated with development workflow

**Verdict**: ACCEPTABLE as interim solution, but not ideal
