# Task P4.2 – Aurora Data API & Vector Migration

## What to Do
- Provision Aurora Serverless v2 cluster via Terraform with Data API enabled and enforce encryption at rest.
- **Migrate RAG vector store from ChromaDB to Aurora `pgvector`** to consolidate state and simplify compliance backups.
- Migrate schema and data from legacy Postgres using AWS DMS or bespoke scripts (validate via checksums).
- Update FastAPI connection layer to use AWS SDK Data API client with Secrets Manager credentials.

## Dependencies
- Depends on Terraform infrastructure baseline (Task 1) and RAG adapters (Task P1.1).

## Best Practices
- Use blue/green deployment to minimize downtime, applying migrations to shadow cluster first.
- Store database credentials only in Secrets Manager; fetch at runtime with caching and rotation support.
- Monitor performance with Performance Insights to ensure throughput meets 50 docs/day requirement.

## Code Example
```python
from botocore.session import Session

session = Session()
client = session.client('rds-data')

def execute_sql(sql, params=None):
  return client.execute_statement(
      resourceArn=os.environ['AURORA_RESOURCE_ARN'],
      secretArn=os.environ['AURORA_SECRET_ARN'],
      database=os.environ['AURORA_DB_NAME'],
      sql=sql,
      parameters=params or [],
  )
```

## Testing Strategy
- Run integration tests in staging hitting Data API; validate transactions, retries, and error handling.
- Execute data reconciliation comparing row counts and checksums pre/post cutover.
- Monitor CloudWatch alarms for throttling or slow queries during first production day.

## Common Issues to Avoid
- Exceeding SQL statement size limits; use batching for large inserts.
- Leaving connections open in legacy drivers, causing pool exhaustion.
- Forgetting to adjust IAM policies for Data API access from ECS task roles.
